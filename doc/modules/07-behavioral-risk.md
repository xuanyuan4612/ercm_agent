# 行为风险模块需求文档

> 文档版本：V3.0
> 所属系统：科沃斯-赫尔墨斯AI系统
> 模块名称：行为风险（Behavioral Risk）

---

## 一、当前流程

### 1.1 现状概述

当前行为风险管理依赖风控人员定期从各监管系统导出行为日志，手动筛选、比对、分析，出具行为风险报告。主要涉及以下数据来源：

| 数据类型 | 来源系统 | 采集方式 |
|----------|----------|----------|
| 文件传输日志 | 文件审计系统 / DLP | 定期导出 CSV/Excel，人工筛选 |
| 文件解密操作日志 | 加密管理系统 | 按需调取，手动关联员工信息 |
| 外发/上传行为日志 | DLP数据防泄漏系统 | 阈值告警后人工核查 |
| 打印/拷贝行为记录 | 终端管控系统 | 按部门不定期抽查 |
| 即时通讯外发记录 | 即时通讯审计系统 | 关键词告警触发后人工追溯 |

### 1.2 当前分析流程

```
风控人员登录各监管系统
    ↓
按部门/时间范围导出行为日志
    ↓
在 Excel 中手动筛选异常记录（如大文件传输、异常时段操作、涉密文件解密）
    ↓
对照 HR 系统核对员工身份、岗位、在职状态
    ↓
排除正常业务操作后，标注可疑行为
    ↓
编写行为风险分析报告（Word），提交管理层审阅
    ↓
月度汇总各系统数据，编写管理报告
```

### 1.3 当前模式的局限性

- 单次分析覆盖范围有限，通常仅针对特定部门或人员
- 跨系统数据关联依赖人工经验，难以发现隐藏的行为模式
- 分析周期长（每次 3-5 个工作日），无法实现高频或实时监控
- 分析质量严重依赖个别风控人员的业务经验，缺乏标准化

## 二、业务痛点

### 2.1 核心痛点

| 痛点 | 描述 |
|------|------|
| **数据量巨大，人工分析不可行** | 各监管系统每日产生海量行为日志（文件传输、解密操作、外发记录、打印记录等），在集团层面动辄百万级/日。风控人员仅能抽样分析，大量异常行为被遗漏 |
| **跨系统信息整合困难** | 异常行为分析需要关联多个维度的信息——行为日志本身（哪个系统、什么操作）、员工身份（HR系统）、岗位职责（德鲁克）、离职状态（风控系统）、亲属关系（利益申报）、商业秘密涉密范围（风控系统）——当前这些信息分散在 5 个以上独立系统中，人工整合耗时且易出错 |
| **缺乏高效分析工具** | 现有工具仅限于 Excel 手工筛选和简单比对，无法实现跨系统自动关联、行为模式挖掘、异常评分排序。同一员工在不同系统的行为碎片无法自动拼合为完整的行为画像 |
| **行为模式识别困难** | 单一行为（如一次文件导出）本身可能正常，但多个弱信号叠加（导出文件 → 申请解密 → 外发给个人邮箱 → 提出离职）才能构成真实风险。人工难以在百万级日志中识别此类组合模式 |
| **历史分析成果无法复用** | 每次分析从零开始，前期已分析过的结果、已排除的正常行为、已确认的风险模式无法沉淀为可调用的知识，导致重复劳动 |
| **报告输出效率低** | 从数据采集、清洗、分析到报告撰写，一份完整的行为风险分析报告耗时 3-5 个工作日，月度管理报告更是需要 1 周以上，时效性不足 |

## 三、建设目标

### 3.1 总体目标

以 AI 智能体为核心，实现跨监管系统行为数据的自动汇聚、智能分析、异常识别与风险定级，将行为风险管理从"人工抽样 + 事后追溯"升级为"智能全覆盖 + 主动发现 + 定期报告"。

### 3.2 具体目标

| 序号 | 具体目标 |
|:---:|----------|
| 1 | 实现跨系统行为数据自动汇聚与关联，打通文件传输、解密、DLP、即时通讯等多源行为数据 |
| 2 | 基于 LLM + RAG 实现员工行为画像构建，自动识别异常行为模式 |
| 3 | 自动完成异常行为风险等级评估（高/中/低），并给出关联分析结论 |
| 4 | 支持按事业部、部门、岗位、人员、角色多维度灵活圈定分析范围 |
| 5 | 月度自动生成行为风险管理情况报告，覆盖监管范围、数据质量、高风险行为、优化建议 |
| 6 | 建立行为风险知识库，沉淀分析经验，支持历史结果回溯与趋势研判 |

| 3 | 风控系统 | 商业秘密信息、涉密文件清单、涉密人员清单 | 涉密行为关联分析：判断员工操作是否涉及涉密文件、是否在涉密权限范围内 |

| 6 | 德鲁克 | 员工岗位职责描述 | 行为与岗位职责匹配分析：判断操作是否超出岗位正常业务范围 |

## 六、主要功能

### 6.1 功能一：行为风险分析

#### 6.1.1 功能概述

用户在辛顿平台选择分析范围（事业部、部门、岗位、人员、角色、分析期间），赫尔墨斯 AI 智能体自动从各监管系统汇聚行为数据，结合员工档案、岗位职责、涉密信息、利益申报等多维度数据，进行跨系统综合分析，识别异常行为，评定风险等级，输出行为风险分析报告。

#### 6.1.2 范围选择参数

| 参数 | 类型 | 说明 |
|------|------|------|
| 事业部 | 多选 | 按事业部维度筛选分析范围 |
| 部门 | 多选 | 按部门维度筛选（与事业部级联） |
| 岗位 | 多选 | 按岗位维度筛选 |
| 人员 | 多选（支持搜索） | 按具体人员（姓名/工号）筛选 |
| 角色 | 多选 | 按角色维度筛选（如高管、涉密人员、关键岗位） |
| 分析期间 | 日期范围 | 行为数据的起止时间范围（默认近 3 个月） |

#### 6.1.3 输入

| 输入项 | 说明 | 来源 |
|--------|------|------|
| 分析范围参数 | 事业部、部门、岗位、人员、角色、期间 | 用户在辛顿平台选择 |
| 行为数据 | 文件传输日志、文件解密日志、DLP 外发日志、打印/拷贝记录、即时通讯审计日志 | 各监管系统 |
| 员工档案信息 | 工号、姓名、邮箱、微信/QQ、手机号、身份证号 | HR系统 / 德鲁克 |
| 部门架构信息 | 事业部、部门、岗位、汇报关系 | MDM / 德鲁克 |
| 岗位职责信息 | 员工岗位职责描述 | 德鲁克 |
| 员工生命周期 | 入职/转岗/离职状态 | 风控系统 |
| 利益申报信息 | 亲属关系、利益冲突申报（含历史档案） | 风控系统 |
| 涉密信息 | 商业秘密信息、涉密文件清单、涉密人员清单 | 风控系统 |
| 历史分析结果 | 前期的行为风险分析结论 | 风控智能体知识库 |
| 行为风险规则 | 异常行为判定规则与风险评分模型 | 知识库 |

#### 6.1.4 AI 分析过程

| 步骤 | 动作 | 说明 |
|:---:|------|------|
| 1 | **多源数据汇聚** | AI 按分析范围参数从各系统拉取行为数据，按员工统一标识（工号/邮箱/手机号）关联，构建每位员工的跨系统行为时间线 |
| 2 | **行为特征提取** | 对每位员工提取关键行为特征：操作类型、操作频次、操作时段、操作对象（是否为涉密文件）、数据量级、外发目标（是否为个人邮箱）等 |
| 3 | **岗位职责匹配** | 将员工行为特征与其岗位职责进行比对，判断操作是否超出正常业务范围（如研发人员大量外发财务数据） |
| 4 | **状态校验** | 校验员工当前在职/离职状态，标记已进入离职流程的人员行为；结合利益申报信息判断是否存在利益冲突风险 |
| 5 | **异常模式识别** | 基于行为风险规则库和 LLM 语义理解，识别异常行为模式。典型模式包括：离职前大量文件导出、非工作时间批量解密涉密文件、向个人邮箱/外部网盘发送业务数据、同一员工多系统同时出现异常等 |
| 6 | **风险等级评估** | AI 综合行为严重程度、涉及数据敏感度、员工状态、历史同类行为等维度，给出风险等级（高/中/低） |
| 7 | **关联分析** | 识别多个员工之间的行为关联（如同一外部收件人、同一时段同类操作），判断是否存在协同作弊风险 |
| 8 | **生成分析报告** | AI 汇总分析结论，自动生成行为风险分析报告 |

#### 6.1.5 输出

| 输出项 | 说明 |
|--------|------|
| 行为风险分析报告 | 包含以下内容的完整分析文档：分析范围与数据概况、异常行为员工清单（含风险等级排序）、每位异常员工的行为时间线（跨系统）、风险行为详情与证据链、关联分析发现（多人协同风险）、综合结论与处置建议 |
| 异常行为明细表 | 结构化 Excel 表格：员工信息、异常行为类型、涉及系统、行为详情、风险等级、判定依据 |
| 风险分布统计 | 按部门/岗位/风险等级等维度的风险分布透视表 |
| 分析操作日志 | 记录本次分析的范围参数、数据源覆盖情况、分析时间、分析耗时，用于后续审计追溯 |

#### 6.1.6 输入输出物总览

| 阶段 | 输入 | 处理 | 输出 |
|:---:|------|------|------|
| 行为风险分析 | 分析范围参数 + 多源行为数据 + 员工档案 + 岗位职责 + 涉密信息 + 利益申报 + 历史分析 + 行为规则 | AI 多源汇聚 → 特征提取 → 岗位匹配 → 状态校验 → 异常识别 → 风险评级 → 关联分析 → 报告生成 | 行为风险分析报告 + 异常行为明细表 + 风险分布统计 + 操作日志 |

### 6.2 功能二：行为风险管理情况报告

#### 6.2.1 功能概述

赫尔墨斯 AI 智能体每月定期自动生成公司整体行为风险管理情况报告，全面总结当月行为风险监控覆盖情况、数据质量、高风险行为事件、高频行为问题及优化建议，为管理层提供全局视角的行为风险管理概览。

#### 6.2.2 生成频率与触发方式

| 属性 | 说明 |
|------|------|
| 生成频率 | 月度（每月初自动生成上月报告） |
| 触发方式 | 定时任务自动触发 + 支持手动触发生成 |
| 报告范围 | 当前周期内所有已接入监管系统的行为数据 |

#### 6.2.3 输入

| 输入项 | 说明 | 来源 |
|--------|------|------|
| 当月行为数据 | 各监管系统当月产生的全量行为日志 | 数据汇聚层 |
| 当月分析结果 | 当月执行的所有行为风险分析报告及异常行为明细 | 风控智能体 |
| 历史管理报告 | 往期管理报告，用于趋势对比和变化分析 | 风控智能体 |
| 监管系统接入状态 | 各监管系统是否正常接入、数据是否按时同步 | 数据汇聚层配置/监控 |

#### 6.2.4 报告内容

| 维度 | 说明 |
|------|------|
| **监管系统覆盖范围** | 已接入的监管系统清单（文件传输、解密、DLP、打印/拷贝、IM审计等），各系统的数据对接状态（正常/延迟/中断），覆盖的员工范围与部门范围 |
| **缺失范围** | 尚未覆盖的监管盲区（如：移动端行为监控、远程办公环境日志、外包人员行为等），建议的后续接入计划 |
| **行为数据质量** | 各系统行为数据的完整性（是否存在数据断档）、及时性（数据同步延迟情况）、准确性（脏数据比例）评估，数据质量趋势变化 |
| **高风险行为展示** | 当月高风险行为事件汇总：事件列表（含人员、部门、行为描述、风险等级）、风险等级分布（高/中/低数量及占比）、与往月的高风险数量对比趋势 |
| **高频行为问题展示** | 频发行为问题分类统计：各类型异常行为的发生次数与占比、TOP 异常行为类型排行、高频部门/岗位分布 |
| **优化方案和建议** | 基于分析结论的管理改进建议：规则优化建议（调整风险判断阈值/新增行为模式）、盲区覆盖建议（优先接入的系统/数据类型）、流程改进建议（针对高频问题提出的制度或流程优化方向） |

#### 6.2.5 输出

| 输出项 | 说明 |
|--------|------|
| 行为风险管理情况报告 | 包含上述 6 个维度的完整管理报告，Word/PDF 格式，含图表（趋势图、分布图、排行图） |
| 报告数据附件 | Excel 格式的底层数据明细，供管理层深入了解具体数据 |
| 报告推送记录 | 报告生成后自动推送至指定管理层人员，记录推送状态 |

#### 6.2.6 输入输出物总览

| 阶段 | 输入 | 处理 | 输出 |
|:---:|------|------|------|
| 管理报告生成 | 当月行为数据 + 当月分析结果 + 历史管理报告 + 系统接入状态 | AI 汇总统计 → 趋势对比 → 质量评估 → 风险梳理 → 建议生成 | 行为风险管理情况报告 + 报告数据附件 + 推送记录 |

### 6.4 碳基守门（HITL — 人工干预节点）

#### 6.4.1 干预节点定义

| 序号 | 干预节点 | 触发场景 | 人工操作 | 结果去向 |
|:---:|----------|----------|----------|----------|
| 1 | **分析报告审核** | AI 完成行为风险分析报告生成后 | 风控人员审核报告内容：确认/修正异常行为判定、调整风险等级、补充或删除分析条目 | 审核通过 → 报告定稿，推送至相关方；审核不通过 → 返回 AI 补充分析或重新生成 |
| 2 | **管理报告审核** | AI 完成月度管理报告生成后 | 风控负责人审核报告数据准确性、建议合理性，确认后发布 | 审核通过 → 报告正式发布并推送；审核不通过 → 返回 AI 修正 |
| 3 | **风险定级修正** | AI 给出的风险等级与实际业务判断不一致时 | 风控人员手动调整风险等级，并填写修正原因 | 修正记录留存，反哺知识库用于规则优化 |
| 4 | **规则调整确认** | 风控人员基于分析经验提出新增或调整行为规则时 | 风控负责人审核新规则的合理性，确认是否纳入规则库 | 审批通过 → 规则入库生效；审批不通过 → 退回修订 |

#### 6.4.2 人工审核闭环

```
AI 生成分析报告 / 管理报告
        │
        ▼
   ┌─ 人工审核 ─┐
   │             │
 通过          不通过 (退回)
   │             │
   ▼             ▼
 定稿发布    AI 补充 / 修正后重新生成
   │             │
   ▼             └──→ 再次提交人工审核
 推送分发
```

## 七、模块间集成

### 7.1 上下游交互关系

行为风险模块在赫尔墨斯系统中处于分析与承接层，既接收风险监控模块推送的行为异常信号，也向离任审计和持续改善模块输出分析结果，同时与风险监控模块形成双向反馈。

```
                   ┌──────────────┐
                   │  2. 风险监控  │
                   │  (主动扫描)   │
                   └──┬───────┬──┘
                      │ 推送  │ 回传
                      ▼       ▲
              ┌───────────┐   │
              │ 7. 行为风险│───┘
              │  (行为分析)│
              └─────┬─────┘
                    │ 推送
          ┌─────────┼─────────┐
          ▼         ▼         ▼
   ┌──────────┐ ┌──────────┐ ┌──────────┐
   │5.离任审计│ │8.持续改善│ │6.商业秘密│
   │(离职审查)│ │(整改跟踪)│ │(保密管理)│
   └──────────┘ └──────────┘ └──────────┘
```

### 7.2 集成详情表

| 上游/关联模块 | 交互方向 | 数据类型 | 触发条件 | 说明 |
|-------------|---------|---------|---------|------|
| 风险监控 → 行为风险 | **接收** | 员工行为异常推送（含异常类型、涉及系统、初步分析） | 风险监控在异常扫描中发现员工行为异常时，自动推送至行为风险模块进行专项深入分析 | 风险监控提供初步异常信号，行为风险模块负责跨系统深度分析，形成"扫描发现 → 专项深挖"的协作模式 |
| 行为风险 → 风险监控 | **推送** | 行为风险分析结果（异常行为确认/排除、风险等级、行为模式） | 行为风险分析完成后，将分析结论回传至风险监控模块 | 分析结论反哺风险监控优化指标和阈值，减少误报。形成"发现 → 分析 → 反馈 → 优化"循环 |
| 行为风险 → 离任审计 | **推送** | 行为风险预警结果（异常行为清单、风险等级、证据摘要） | 离任审计问题清单生成阶段，自动拉取行为风险模块的分析结果 | 离任审计中的人员行为审查可复用行为风险模块的分析成果，避免重复分析。行为风险预警结果直接作为离任审计问题清单的输入之一 |
| 行为风险 → 持续改善 | **推送** | 行为风险问题清单（需整改的行为问题、涉及部门/人员、整改建议） | 行为风险分析中发现的需要整改的行为问题 | 涉及制度或流程改进的行为问题汇入持续改善模块统一跟踪闭环 |
| 行为风险 → 商业秘密 | **推送** | 涉密行为异常预警（涉密文件异常操作、超权限访问等） | 行为分析中识别出涉密文件相关的异常行为时 | 涉密行为异常可触发商业秘密模块的定密评审或预警处置 |
| 德鲁克（HR） → 行为风险 | **接收** | 员工档案、岗位职责、部门架构 | 行为风险分析启动时，按需拉取 | 通过 A2A 智能体通信获取 HR 侧数据，用于员工身份校验与岗位匹配 |

## 八、关键成功指标（KPIs）

| 指标 | 目标 | 说明 |
|------|:----:|------|
| 行为异常识别准确率 | ≥ 85% | AI 标记的异常行为中，经人工审核确认为真实风险的比例。通过持续优化规则和积累历史数据不断提升 |
| 跨系统数据整合覆盖率 | ≥ 90% | 已接入并正常同步的监管系统占计划接入系统的比例。优先接入文件传输、解密、DLP 三大核心系统 |
| 分析报告生成效率 | ≤ 30 分钟/次 | 从发起分析到生成完整报告的时间。相比人工分析（3-5 天），效率提升 200 倍以上 |
| 月度管理报告生成时效 | 每月前 3 个工作日内完成 | 月度报告自动生成并完成人工审核的时间要求 |
| 风险遗漏率 | ≤ 5% | AI 标记为正常但在后续审计中被发现为真实风险的比例。越低越好，通过规则迭代持续降低 |
| 分析覆盖员工比例 | ≥ 95% | 在分析范围内，有行为数据可供分析的员工占比。受数据源接入情况影响 |
| 知识库规则活跃度 | 季度更新 ≥ 1 次 | 行为风险规则库的更新频率，反映规则优化与经验沉淀的活跃程度 |
| 模块间推送成功率 | ≥ 99% | 向风险监控、离任审计、持续改善等模块推送分析结果的接口调用成功率 |
